# ADR-0001: Record Architecture Decisions

* Status: accepted
* Date: 2026-03-29

## Context

We need to record the architectural decisions made on this project so that future contributors can understand the reasoning behind design choices.

## Decision

We will use Architecture Decision Records (ADRs) as described by Michael Nygard in his article "Documenting Architecture Decisions". ADRs are stored in `docs/adr/` and numbered sequentially. Each ADR describes the context, decision, and consequences.

## Consequences

- Architectural decisions are transparent and discoverable
- New contributors can understand why things are the way they are
- Decisions can be revisited and superseded with a clear trail
- Small overhead to create a new ADR for each significant decision
